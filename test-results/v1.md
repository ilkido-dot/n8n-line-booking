Date: 2026-11-03 · n8n 2.44.4 (self-hosted, Docker) · Model: Claude Haiku 5.5 · 17 tests, 21 messages

All tests fix "now" at 2026-11-03 (Tue) 15:00 Asia/Taipei, so relative dates have fixed answers:
tomorrow = 11/4, this Friday = 11/6, this Saturday = 11/7, next Saturday = 11/14.

### The one failure (run 4, T16)

Message: `下週六晚上7點 6位 王小明 0912345678，請問有低消嗎？` (next Saturday, 7 pm, 6 people).

Haiku returned `"date_kind": "weekday", "week": "next", "weekday": null`: it marked "next week" but left out which day.
`Decide` did not guess the day. It answered "日期我不太確定是哪一天" and asked for the date again,
and nothing was written to `bookings`.

Cause: the prompt only said "weekday is 1 to 7" on the "this Saturday" line. The "next Saturday" line only mentioned `week`.
Fix: one rule for any weekday ("weekday must be filled, Monday 1 … Saturday 6 … Sunday 7"), with the example
`下週六 → week "next", weekday 6`. Runs 5 to 7 passed.

## 4. Webhook and signature checks (local, before connecting LINE)

The workflow was published on the local n8n and requests were sent from the browser to `/webhook/line-booking`,
signed with a test secret stored in the Crypto credential.

| Request | Result |
|---|---|
| Correct signature, no events | `Sign Body` output matched the signature sent; nothing processed |
| Wrong signature, text event | dropped at `Check Signature` |
| No signature, text event | dropped at `Check Signature` |
| Correct signature, text event | went through Haiku, `Decide` (save_draft), `Save Draft`, then failed at `Reply to LINE` with 401 because the token was still a placeholder |
| Correct signature, sticker | `Fixed Reply`, then 401 at `Reply to LINE` (same reason) |

The two 401 errors also triggered the error workflow, which pushed an alert to the separate LINE alert account.
The test draft row was deleted afterwards.

## 5. Checks outside n8n

`local-tests/run.js` runs the Code node files in Node with the n8n variables (`$input`, `$('…')`) replaced by stubs,
and with hand-written "correct" AI outputs, so it tests the program, not the model:

- the 17 tests through Test Messages, Prepare, Decide and Grade: 17 / 17
- 21 date, time and phone edge cases (for example "1/5" said on 12/28 is next year, 中午1點 is 13:00, +886 and full-width digits, 2/30, "next week" with no weekday, a draft date that is now in the past, AI output that is not JSON)
- drafts older than 24 hours are dropped
- signature comparison: correct, wrong and missing signatures; standby and group events are skipped

## Known limits

- The 21 messages are simulated. I listed most scenarios (complete booking, missing people, missing date, 明天, 這週六, people in Chinese numerals, two-message booking, price question, prompt injection); Claude added the rest (past date, over 20 people, bad phone, out of hours, time already passed today, next Saturday, cancellation) and wrote the message text.
- Reply wording is fixed templates, so it is not graded for tone.
